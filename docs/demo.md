# Демонстрация «ВышКат»

Сценарий показывает добавление транспорта и вещей, техосмотр, отчёты,
список для новичков, ведомость и обработку ошибок ввода.

Команды ниже выполняются из корня проекта. Нужна Go 1.26 или новее.
Баланс хранится в памяти: каждая новая сессия начинается с пустого парка.

## Интерактивный запуск

```bash
go run -buildvcs=false ./cmd/escooter-sharing
```

Выберите номер действия и вводите ответы по одному на строку, завершая Enter.
Названия могут содержать пробелы. Инвентарные номера уникальны для всего
баланса. Техническое состояние вводится как `да` или `нет`, простота — целым
числом от 1 до 10, суточная энергия — конечным неотрицательным числом.
Десятичный разделитель может быть точкой или запятой.

Ошибка ввода отменяет текущее добавление и возвращает главное меню.
Для повторения нужно заново выбрать действие. `0` завершает программу
в главном меню; внутри вопроса это введённое значение, например нулевая энергия.

## Воспроизводимая демонстрация

```bash
go run -buildvcs=false ./cmd/escooter-sharing < docs/demo/session.txt
```

В [`session.txt`](demo/session.txt) уже записаны все ответы, включая намеренно
пустые строки для ошибочного ввода. Сохраняйте их при копировании.
При перенаправлении ввода ответы не дублируются в выводе программы;
их можно сопоставить с вопросами по этому файлу.

Сценарий выполняет следующие действия:

| Шаг | Ввод в меню | Что показывает |
| --- | --- | --- |
| Пустой парк | `2`, `3`, `5`, `8` | Пустые списки и нулевой отчёт |
| Неизвестная команда | `99` | Подсказка о доступных действиях; работа продолжается |
| Велосипед B-5 | `1`, `B-5`, `Спортивный велосипед`, `да`, `5` | Допущен, но не подходит новичкам |
| Велосипед B-6 | `1`, `B-6`, `Городской велосипед`, `да`, `6` | Допущен и подходит новичкам на границе правила |
| Самокат S-1 | `4`, `S-1`, `Электросамокат`, `да`, `8`, `1.5` | Допущен; расход 1,5 кВт·ч/сутки |
| Электровелосипед E-1 | `9`, `E-1`, `Электровелосипед`, `нет`, `10`, `2,25` | Сохраняется на балансе после отказа; недоступен в прокат |
| Шлем H-1 | `6`, `H-1`, `Синий шлем` | Добавляется без техосмотра и потребления энергии |
| Станция C-1 | `7`, `C-1`, `Зарядная станция`, `3.25` | Добавляется без техосмотра; её энергия входит в общий баланс |
| Повтор номера | Шлем с номером `B-6` | Нельзя занять номер уже существующего транспорта |
| Ошибочные данные | Простота `11` и `шесть`, состояние `может быть`, энергия `-1` и `abc`, пустые название и номер | Понятные ошибки; записи X-1–X-6 не появляются на балансе |
| Проверка результата | `2`, `3`, `5`, `8` | Показатели и ведомость после всех успешных и ошибочных действий |
| Выход | `0` | Сообщение о завершении программы |

Итоговый отчёт должен содержать:

```text
Всего объектов на балансе: 6
Вещей на балансе: 2
Транспорта на балансе: 4
Допущено в активный парк: 3
Отклонено техосмотром: 1
Суточная энергия всего баланса: 7 кВт·ч/сутки
Суточная энергия активного транспорта: 1.5 кВт·ч/сутки
```

Активный парк содержит B-5, B-6 и S-1. В списке для новичков остаются только:

```text
B-6 — Городской велосипед (простота: 6/10)
S-1 — Электросамокат (простота: 8/10)
```

Инвентарная ведомость содержит весь баланс, включая отклонённую технику:

```text
B-5 — Спортивный велосипед
B-6 — Городской велосипед
C-1 — Зарядная станция
E-1 — Электровелосипед
H-1 — Синий шлем
S-1 — Электросамокат
```

После восьми ошибок добавления показатели остаются именно такими.
Общий расход — сумма характеристик S-1, E-1 и C-1: 1,5 + 2,25 + 3,25 = 7.
Это заданная суточная энергия объектов на балансе, а не фактический замер
работы неисправного E-1. Энергия активного транспорта учитывает только S-1.

## Завершение ввода посреди добавления

```bash
go run -buildvcs=false ./cmd/escooter-sharing < docs/demo/incomplete.txt
```

В [`incomplete.txt`](demo/incomplete.txt) выбрано добавление шлема и введён
номер H-EOF, но отсутствует название. Программа завершится без ошибки процесса,
выведет сообщение о конце ввода и не подтвердит создание вещи.
Незавершённое добавление не меняет баланс.

Файлы демонстрации проверяются тестами
[`internal/bootstrap/demo_test.go`](../internal/bootstrap/demo_test.go).
Ошибки чтения/записи консоли и сохранность баланса дополнительно проверяются
в [`internal/cli/stream_test.go`](../internal/cli/stream_test.go).
